# Регламент технического обслуживания (ТО) информационной системы «Векторный калькулятор»

## 1. Паспортная часть и общие положения

### 1.1. Назначение документа
Настоящий Регламент определяет порядок, периодичность, содержание работ и зоны ответственности специалистов при техническом обслуживании информационной системы «Векторный калькулятор» (далее — ИС). 
Целями внедрения регламента являются:
* Минимизация простоев и сбоев при обработке векторных данных.
* Обеспечение безопасности и целостности данных (резервное копирование векторов).
* Соблюдение требований технического задания (ТЗ).
* Обеспечение воспроизводимости и точности результатов сложения векторов в N-мерном пространстве.

### 1.2. Область применения
Правила настоящего Регламента распространяются на:
* **Программное обеспечение:** Python 3.10+, консольная программа `vector_calc.py`, модули ввода-вывода (консоль/файл), модуль математических вычислений, модуль резервного копирования.
* **Аппаратное обеспечение:** ПК/сервер разработчика и эксплуатации, файловая система для хранения файлов ввода/вывода и резервных копий.
* **Документацию:** ТЗ (`TERMS_OF_REFERENCE.md`), руководства пользователя (`README.md` на русском и английском языках), тест-кейсы.

### 1.3. Роли участников
* **Разработчик:** обновление кода, исправление дефектов, актуализация документации.
* **Специалист по ТО:** выполнение плановых работ, ведение журналов, запуск тестов.
* **Администратор:** резервное копирование, восстановление данных, контроль доступа к файлам.
* **Пользователь:** корректный ввод данных, сообщение об инцидентах.

## 2. Технологические карты ТО (основной раздел)

Документ разделяет работы на два вида по стратегии и частоте выполнения:
* **Плановое (профилактическое) ТО (ППР):** календарные работы для предотвращения сбоев.
* **Внеплановое (инцидентное) ТО:** аварийные работы при возникновении ошибок или отказов ИС.

| № | Наименование операции | Периодичность | Вид ТО | Пошаговый алгоритм и ожидаемый результат | Инструменты |

| 2 | Контроль свободного места на диске | Ежедневно | Плановое | Проверка свободного места (не менее 10%); при нехватке — очистка старых бэкапов | `df -h` / проводник |
| 3 | Валидация модуля сложения векторов (эталонный тест) | Еженедельно | Плановое | Ввод двух векторов размерности N, сверка длины и координат с эталоном; ожидается совпадение | `pytest`, тест-кейсы |

### 2.2. Алгоритм резервного копирования и восстановления пространственных векторов

**Резервное копирование:**
1. Определить каталог данных (файлы входных векторов и результатов).
2. Создать каталог `backup/YYYY-MM-DD_HH-MM/`.
3. Скопировать файлы, вычислить SHA-256 для каждого.
4. Записать манифест `manifest.json` (список файлов + хеши + метка времени).
5. Проверить совпадение хешей; при расхождении — повторить копирование.

**Восстановление:**
1. Выбрать резервную копию по метке времени.
2. Проверить целостность по `manifest.json`.
3. Развернуть файлы в рабочий каталог.
4. Запустить эталонный тест сложения векторов; ожидается совпадение с эталоном.

## 3. Контроль качества и отчетность

### 3.1. Параметры контроля
* Корректность длины вектора-результата (вычисляется по формуле).
* Корректность координат: r_i = a_i + b_i для всех i = 1..N.
* Успешность обмена данными консоль/файл — 100% сценариев.
* Целостность резервных копий — совпадение SHA-256.
* Отсутствие критических записей в логах за сутки.
* Время отклика программы на операцию сложения — не более 1 с при N <= 10^4.

### 3.2. Формы документов
* Журнал выполненных работ ТО.
* Акт технического состояния ИС (ежемесячно).
* Отчет об инциденте (при внеплановом ТО).
* Отчет о тестировании ключевых модулей.
